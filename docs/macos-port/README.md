# VoiceDrop на macOS — как начать

VoiceDrop — приложение для диктовки: зажал клавишу, говоришь, отпустил — текст распознаётся и вставляется в любое активное окно. Оригинал сделан под Windows и распознаёт речь через платный онлайн-сервис ElevenLabs.

Цель порта — **та же механика на MacBook, но с локальной бесплатной моделью Whisper от OpenAI**: без подписки, без API-ключей, работает офлайн, голос никуда не уходит.

Порт делается в **вашем форке** с помощью Claude Code в терминале. Всё нужное лежит в этой папке:

| Файл | Что внутри |
|---|---|
| [`PLAN.md`](PLAN.md) | План порта: что в коде завязано на Windows, чем это заменить на маке, этапы с критериями готовности, риски. |
| [`PROMPTS.md`](PROMPTS.md) | Готовые промпты для Claude Code — по одному на этап, вставляете по очереди. |

## Что понадобится

- MacBook на Apple Silicon (M1 и новее) с macOS 14 или новее — лучший вариант: Whisper считается на GPU чипа. На Intel тоже заработает, но только на процессоре и заметно медленнее.
- 5–10 ГБ свободного места (модели Whisper весят от ~150 МБ до ~3 ГБ).
- Аккаунт GitHub, `git`, Python 3.12 или 3.13.
- Claude Code: установка по официальной инструкции на [claude.com/claude-code](https://claude.com/claude-code).
- API-ключи **не нужны**. Ключ Anthropic понадобится только если захотите оставить опциональную LLM-полировку текста.

## Порядок действий

1. Нажмите **Fork** на странице репозитория на GitHub — у вас появится своя копия.
2. Склонируйте форк и откройте Claude Code в его папке:
   ```bash
   git clone https://github.com/<ваш-логин>/VoiceDrop.git
   cd VoiceDrop
   claude
   ```
3. Откройте [`PROMPTS.md`](PROMPTS.md) и вставьте **Промпт 0**. Дальше — по одному промпту на этап. Не переходите к следующему, пока этап не прошёл свой критерий готовности: Claude сам скажет, что проверить руками.
4. После каждого этапа Claude делает коммит. Если что-то сломалось — всегда можно откатиться на предыдущий.

## Про разрешения macOS

macOS не даст приложению слушать клавиатуру и вставлять текст без явного разрешения. В процессе вы несколько раз зайдёте в **Системные настройки → Конфиденциальность и безопасность** и включите доступ в разделах **Микрофон**, **Универсальный доступ** и **Мониторинг ввода** — для Терминала на время разработки, потом для собранного приложения. Claude подскажет, когда и что именно включить. Это нормально: так macOS защищает любые приложения, которые читают клавиатуру и управляют другими окнами.

## Если что-то пошло не так

Опишите Claude симптом своими словами и приложите последние строки `voicedrop.log` из папки проекта. В оригинале много защитной логики (ретраи микрофона, защита от гонок хоткея) — [`PLAN.md`](PLAN.md) объясняет, какую её часть сохранить.
