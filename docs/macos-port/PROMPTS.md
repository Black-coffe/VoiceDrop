# Промпты для Claude Code

Вставляйте по одному, по порядку, в Claude Code, открытый в папке вашего форка. План, на который ссылаются промпты, — [`PLAN.md`](PLAN.md).

После каждого этапа Claude говорит, что проверить руками. Проверьте, и только потом вставляйте следующий промпт. Если проверка не прошла, опишите, что увидели, и попросите исправить в рамках этого же этапа.

---

## Промпт 0 — разведка и окружение

```text
Мы портируем VoiceDrop (Windows-приложение для диктовки push-to-talk) на macOS с локальной
бесплатной моделью Whisper вместо ElevenLabs. Это мой форк, я работаю на MacBook.

Прочитай docs/macos-port/PLAN.md целиком, потом README.md и main.py, core/, gui/, tests/.

Сделай этап 0 плана:
1. Определи чип и версию macOS (uname -m, sw_vers, sysctl -n machdep.cpu.brand_string)
   и по таблице «Выбор движка Whisper» скажи, какой движок берём.
2. Создай venv (.venv) на Python 3.12 или 3.13. Поставь из requirements.txt только то, что ставится
   на macOS (pywin32, pycaw — Windows-only; вынеси их в маркер `; sys_platform == "win32"`).
3. Прогони тесты: python -m unittest discover -s tests -t . — и составь список:
   какие зелёные, какие падают и из-за какой Windows-зависимости.
4. Создай CLAUDE.md для этого форка: команды (venv, тесты, запуск), архитектура
   (потоки, флаги под локом, пайплайн, конфиги рядом с приложением), и что мы портируем
   на macOS по docs/macos-port/PLAN.md. Коротко, без общих советов.

Код приложения на этом этапе не меняй, кроме requirements.txt. В конце — коммит и отчёт.
```

## Промпт 1 — платформенный слой

```text
Этап 1 из docs/macos-port/PLAN.md: платформенный слой.

Цель: приложение импортируется и тесты проходят на macOS, при этом поведение на Windows
не меняется ни на байт.

- Заведи пакет platform_support/ с интерфейсами: вставка текста, имя активного приложения,
  автозапуск, mute, звуковой сигнал (замена winsound.Beep — в main.py 13 вызовов),
  единственный экземпляр (сейчас Windows-mutex в начале main.py), рабочая область экрана
  (для оверлея). Выбор реализации — по sys.platform.
- Windows-реализации — перенеси текущий код как есть. macOS — пока безопасные заглушки
  с логированием (реальные реализации будут на этапах 3 и 5).
- Импорты winreg, ctypes.windll, pycaw, winsound — только внутри Windows-реализаций.
- Windows-специфичные тесты пометь @unittest.skipUnless(sys.platform == "win32", ...).
  Новые тесты — на выбор реализации по платформе.

Критерий готовности: `python -c "import main"` без ошибок, все не-Windows тесты зелёные.
Покажи диф, объясни, как проверено, что Windows-путь не изменился. Коммит.
```

## Промпт 2 — локальный Whisper

```text
Этап 2 из docs/macos-port/PLAN.md: локальное распознавание Whisper.

Перед кодом проверь API по документации (context7 или официальный репозиторий + PyPI).
Не пиши вызовы по памяти. Проверь:
- для mlx-whisper: сигнатуру transcribe, приём numpy float32 16 kHz, параметры language
  и initial_prompt, имя репозитория модели на Hugging Face;
- для запасного движка (pywhispercpp или faster-whisper) — то же самое.
Версии, с которыми работаешь, зафиксируй в requirements.

Сделай:
- core/stt_local.py: класс с тем же интерфейсом, что ElevenLabsClient.transcribe(audio_data: bytes,
  language) -> str (на входе WAV-байты из AudioRecorder). Движок выбирается настройкой stt_engine,
  на маке по умолчанию — по чипу (Apple Silicon → mlx-whisper). Модель — настройка whisper_model,
  по умолчанию large-v3-turbo; модель всегда указывать явно.
- Загрузка модели и прогрев — один раз, в фоне при старте, с логом прогресса. Первое нажатие
  до готовности модели — понятная ошибка, а не зависание.
- В main.py выбери клиента STT по настройке. Realtime-WebSocket и офлайн-очередь при локальном
  движке не используются: сеть не нужна. «Переписать последнее» должно работать через локальный движок.
- Юнит-тесты с моком движка + scripts/bench_stt.py: прогон WAV-файла, вывод текста и времени.

Критерий готовности: тесты зелёные; я запишу по фразе на RU, UK и EN (скажи, как записать WAV
на маке) — bench выдаёт правильный текст; покажи время на каждой модели. Коммит.
```

## Промпт 3 — хоткей и вставка: первый сквозной MVP

```text
Этап 3 из docs/macos-port/PLAN.md: хоткей и вставка на macOS. Цель — первая рабочая
диктовка из терминала, пока без menu bar.

Перед кодом проверь по документации pynput раздел macOS limitations и keyboard.

- hotkey_manager: на macOS хранить хоткей именами клавиш pynput, а не Windows VK. По умолчанию —
  правый Option (Key.alt_r; на macOS он совпадает с Key.alt_gr, vk 0x3D — сравнивай с обоими).
  Модификатор «режима кода» — Key.shift_r. Нормализация VK 161/163/165/92 — только для Windows.
  Сохрани точное различение левых и правых модификаторов и логику modifier_was_held().
- Вставка на macOS: сохранить буфер → pyperclip.copy(text) → синтетический Cmd+V → восстановить буфер
  после небольшой паузы. Режимы из оригинала: в окно / только буфер / в окно + Enter.
- Звуки старта, стопа и ошибки на macOS через platform_support (afplay системного звука или NSSound).
- Если нет разрешения Accessibility, приложение пишет это в лог и показывает понятное сообщение,
  а не молча не работает.

Не трогай флаги _is_recording / _is_processing / _record_session_id и порядок «сначала захват».
Скажи мне точно, какие разрешения включить для терминала, и дай чек-лист ручной проверки:
TextEdit, Notes, браузер, мессенджер, быстрые повторные нажатия, режим кода. Коммит.
```

## Промпт 4 — menu bar и окна

```text
Этап 4 из docs/macos-port/PLAN.md: menu bar, настройки, история.

Проблема: на macOS pystray должен работать в главном потоке (у него есть run_detached),
и Tk mainloop тоже хочет главный поток. Сначала спайк, потом решение:
- Вариант A: pystray run_detached + Tk mainloop в главном потоке. Проверь реальным запуском
  и открытием/закрытием окон несколько раз.
- Вариант B: rumps (menu bar) в главном потоке. Окна настроек и истории (customtkinter) —
  в отдельном процессе (python -m gui.settings_window / gui.history_window); обмен — через
  settings.json и БД, которые и так перезагружаются на лету.
Сначала проверь по докам pystray (usage, FAQ) и rumps. Выбери вариант по результату спайка
и объясни почему.

Перенеси меню трея полностью (tray_icon.py): режим, вставка, язык, скопировать последнее,
переписать последнее, полировка, автозапуск, сохранение истории, настройки, выход.
Пункты, которые на маке не имеют смысла (расход ElevenLabs, очередь), скрой при локальном
движке. Статус записи — иконка или заголовок в menu bar. Иконку в Dock не показывать.

Настройки: список микрофонов, язык, хоткей (захват клавиши работает через pynput-имена),
выбор модели Whisper. Коммит.
```

## Промпт 5 — mute, автозапуск, единственный экземпляр

```text
Этап 5 из docs/macos-port/PLAN.md.

- Mute на macOS: опциональная настройка mute_system_output (по умолчанию false). При записи —
  osascript "set volume output muted true", после — вернуть ТО состояние, что было до записи.
  Сохрани гарантии оригинала: grace-период, самоотмена позднего mute, страховочный unmute
  при старте, если прошлый запуск упал посреди записи. Заглушение отдельных приложений
  (Core Audio taps) — не делаем, это бэклог.
- Автозапуск: LaunchAgent в ~/Library/LaunchAgents (формат plist проверь по документации Apple)
  или Login Item — выбери и объясни. Пункт меню включает и выключает.
- Единственный экземпляр: lock-файл через fcntl вместо Windows-mutex.
- Оверлей записи — только если выбранный на этапе 4 вариант позволяет. Иначе оставь
  статус в menu bar и запиши оверлей в бэклог.

Тесты на логику mute (восстановление прежнего состояния, поздний mute) с моком osascript. Коммит.
```

## Промпт 6 — сборка .app

```text
Этап 6 из docs/macos-port/PLAN.md: сборка VoiceDrop.app.

Проверь по документации PyInstaller (spec-files, feature-notes) и Apple:
- BUNDLE в spec-файле для macOS (отдельный VoiceDrop-macos.spec, Windows-spec не трогать);
- info_plist: NSMicrophoneUsageDescription, LSUIElement (без иконки в Dock);
- подпись: ad-hoc для личного использования. Если подписываем сертификатом с hardened runtime —
  entitlement com.apple.security.device.audio-input, иначе система завершит приложение при доступе
  к микрофону.

Данные и конфиги — в ~/Library/Application Support/VoiceDrop (а не рядом с .app).
Модель Whisper — вне бандла, в кэше. Перенастрой BASE_DIR/APP_DIR для собранного приложения
на macOS, dev-режим оставь как есть.

Напиши docs/macos-port/INSTALL.md для пользователя: сборка, перенос в /Applications,
выдача разрешений (Микрофон, Универсальный доступ, Мониторинг ввода), что делать,
если после пересборки macOS снова спрашивает разрешения. Коммит.
```

## Промпт 7 — качество распознавания

```text
Этап 7 из docs/macos-port/PLAN.md: качество.

- Словарь терминов для распознавания: если движок поддерживает initial_prompt (проверь по докам),
  подавай туда термины из keyterms.json — это аналог keyterms ElevenLabs. Кнопка включения
  есть в настройках. replacements.json и commands.json работают как раньше.
- Язык: Авто / RU / UK / EN. Проверь «Переписать последнее» на смешанной RU/UK речи.
- Короткие клипы: Whisper иногда выдаёт «галлюцинации» на тишине (типичные фразы вроде
  благодарностей за просмотр). Отфильтруй пустые и тихие клипы по уровню до распознавания
  и известные фразы-галлюцинации после.
- Полировка через Claude (TextPolisher) остаётся опциональной: работает, только если в .env
  есть ANTHROPIC_API_KEY.

Дай мне 10 тестовых фраз для ручной проверки и сравни результат с/без initial_prompt. Коммит.
```
