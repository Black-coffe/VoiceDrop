# План порта VoiceDrop на macOS с локальным Whisper

Документ для человека и для Claude Code. Промпты по этапам — в [`PROMPTS.md`](PROMPTS.md).

## Цель и рамки

**Результат:** menu bar-приложение для macOS. Пользователь зажимает клавишу и говорит, отпускает — речь распознаётся **локальной** моделью Whisper, текст проходит ту же постобработку, что в оригинале, и вставляется в активное окно.

**Требования:**
- Никаких платных сервисов и ключей по умолчанию. Всё работает офлайн, аудио не покидает машину.
- Сохраняется механика и защитная логика оригинала: гонки хоткея, ретраи микрофона, пайплайн постобработки, история.
- Windows-путь в форке не ломаем: платформенный код уходит за общий интерфейс. Тогда в форк можно будет подтягивать обновления из оригинала.

**Вне рамок первой версии:**
- realtime-распознавание по WebSocket (это функция ElevenLabs);
- офлайн-очередь досылки (локальной модели сеть не нужна);
- учёт расходов;
- подпись и нотаризация для публичного распространения.

## Как устроен оригинал (коротко)

- **`main.py` → `VoiceDropApp`** — оркестратор, владеет потоками и состоянием. Tk mainloop работает в главном потоке, pystray — в своём потоке, колбэки хоткея (pynput) — в потоке листенера. Каждый клип обрабатывается в отдельном daemon-потоке. UI из чужих потоков вызывается только через `root.after(0, …)`.
- **Флаги `_is_recording` / `_is_processing` / `_record_session_id` под локом.** Нажатие во время обработки отклоняется. Захват микрофона стартует первым, до всего остального.
- **`core/audio_recorder.py`** — запись через sounddevice. Микрофон резолвится по имени, открывается на нативной частоте, есть ретраи. На выходе WAV-байты 16 kHz mono.
- **`core/elevenlabs_api.py`** — `ElevenLabsClient.transcribe(audio_data: bytes, language) -> str`. **Сюда встаёт локальный Whisper с тем же интерфейсом.**
- **`core/pipeline.py`** — `TextPipeline`, чистое преобразование без UI: полировка → словарь → голосовые команды → код-стиль. Переносится без изменений.
- **Конфиги рядом с приложением:** `settings.json`, `replacements.json`, `commands.json`, `profiles.json`, `keyterms.json`, `mute_whitelist.json`. Перезагружаются на лету по сравнению содержимого.

## Что завязано на Windows и чем заменить

| Место в коде | Windows сейчас | macOS | Уверенность |
|---|---|---|---|
| `core/elevenlabs_api.py` | Онлайн-STT ElevenLabs | Новый `core/stt_local.py` с тем же `transcribe()`: **mlx-whisper** на Apple Silicon, whisper.cpp (pywhispercpp) или faster-whisper на CPU для Intel | Проверено, см. ниже |
| `core/hotkey_manager.py` | VK-коды Windows, нормализация 161/163/165/92 | pynput `Key`: по умолчанию **правый Option** (`Key.alt_r`; на маке это та же клавиша, что `Key.alt_gr`, vk 0x3D — сравнивать с обеими). Модификатор кода — правый Shift или правый Cmd (`Key.cmd_r`, vk 0x36) | Проверено |
| `core/text_inserter.py` | `keybd_event` Ctrl+V, проверка фокуса через `GetGUIThreadInfo` | pyperclip + синтетический **Cmd+V** (pynput Controller или Quartz `CGEventPost`) — нужно разрешение Accessibility. Проверку фокуса на первом этапе убрать или сделать через Accessibility API | Проверено |
| `core/profiles.py` | `GetForegroundWindow` + psutil | Активное приложение через `NSWorkspace.sharedWorkspace().frontmostApplication()` (PyObjC) | Проверить по докам |
| `core/audio_muter.py` | pycaw, заглушение отдельных приложений | **MVP:** опциональный mute системного вывода (`osascript -e "set volume output muted true"`), по умолчанию выключен, с восстановлением прежнего состояния. **Позже:** Core Audio process taps (macOS 14.2+, `CATapDescription.muteBehavior`) — нужен helper на Swift или PyObjC, ключ `NSAudioCaptureUsageDescription` и отдельное разрешение | Проверено |
| `core/autostart.py` | Ключ реестра `HKCU\…\Run` | LaunchAgent (`~/Library/LaunchAgents/*.plist`) или Login Item | Проверить по докам |
| `gui/tray_icon.py` + Tk-окна | pystray в потоке, Tk в главном | Конфликт: pystray на маке обязан работать в главном потоке (есть `run_detached`), Tk тоже. **Решается спайком на этапе 4** | ⚠️ Конфликт не подтверждён вторым источником |
| `gui/recording_overlay.py` | Tk + WinAPI рабочей области монитора | MVP: состояние в иконке menu bar + звуки. Позже — оверлей | Решение по спайку |
| `main.py` | `winsound.Beep` (13 мест), mutex, AppUserModelID, crash-лог | Звуки через `afplay`/NSSound, единственный экземпляр через lock-файл (`fcntl`), AppUserModelID не нужен | Проверить по докам |
| `audio_recorder.py` | Приоритет host API: MME → WASAPI → … | На маке один host API (Core Audio). Приоритет сделать платформенным, резолв по имени оставить | Проверить на машине |
| `VoiceDrop.spec` | onefile `.exe` | PyInstaller `BUNDLE` → `.app` с `info_plist`, где есть `NSMicrophoneUsageDescription`. При подписи настоящим сертификатом включается hardened runtime — нужен entitlement `com.apple.security.device.audio-input` | Проверено |

## Выбор движка Whisper

Модели Whisper и их код открыты под лицензией **MIT**. `large-v3-turbo` — официальная модель OpenAI (809M параметров).

| Чип | Движок | Почему |
|---|---|---|
| **Apple Silicon (M1+)**, macOS 14+ | **mlx-whisper** (PyPI `mlx-whisper`), модель `mlx-community/whisper-large-v3-turbo` (~1.6 ГБ) | Считает на GPU чипа через MLX. Принимает numpy float32 16 kHz напрямую: `mlx_whisper.transcribe(audio, path_or_hf_repo=..., language="ru")["text"]`. MLX работает только на Apple Silicon и требует macOS ≥ 14 |
| **Intel** | whisper.cpp через **pywhispercpp** или **faster-whisper** на CPU | У pywhispercpp на PyPI колёса для macOS есть только под arm64, для Intel нужна сборка из исходников. faster-whisper на маке работает только на CPU (MPS-бэкенд CTranslate2 пока экспериментальный и не попал в колёса). Брать модели поменьше |

**Замечания:**
- Внутри mlx-whisper по умолчанию стоит модель `mlx-community/whisper-turbo`, а не `whisper-tiny`, как написано в README. Модель всегда указывать явно.
- В колёсах pywhispercpp Metal может не подхватиться (issue #59) и тихо уйти на CPU. Если на Apple Silicon выбран он, это проверяется по логу инициализации.
- Движок прячется за интерфейсом `transcribe(bytes, language) -> str`. Замена движка или модели — это строчка в `settings.json` (`stt_engine`, `whisper_model`), а не правка кода.
- Модель загружается **один раз при старте** в фоне и держится в памяти. Первый запуск скачивает веса — показать это в menu bar.
- Скорость на конкретном маке не обещаем — замеряем на этапе 2 (готовая строка лога `Pipeline …` из оригинала это покажет).

Версии на момент написания (PyPI, 2026-09-29): mlx-whisper 0.4.3, pywhispercpp 1.5.1, faster-whisper 1.2.1, pynput 1.8.2, pystray 0.19.5, rumps 0.4.0, pyinstaller 6.22.3, sounddevice 0.5.6.

## Разрешения macOS

| Разрешение | Зачем | Когда просить |
|---|---|---|
| Микрофон | Запись | Первый запуск записи |
| Универсальный доступ (Accessibility) | Listener pynput проверяет `AXIsProcessTrusted()`; синтетический Cmd+V | До первого теста хоткея |
| Мониторинг ввода (Input Monitoring) | Глобальный listener клавиатуры | Вместе с Accessibility — надёжнее выдать оба |

Пока идёт разработка из терминала, разрешения выдаются **приложению терминала**. Для собранного `.app` — заново, уже самому приложению.

## Этапы

У каждого этапа есть критерий готовности. Следующий этап не начинается, пока текущий не проходит его на реальном маке. После каждого этапа — коммит.

| # | Этап | Критерий готовности |
|---|---|---|
| 0 | **Разведка и окружение.** Определить чип и версию macOS, создать venv, CLAUDE.md для форка, прогнать тесты и зафиксировать, какие падают из-за Windows | Есть CLAUDE.md, отчёт по тестам, выбран движок |
| 1 | **Платформенный слой.** Пакет `platform_support/` (или аналог) с интерфейсами: вставка, активное приложение, автозапуск, mute, звук, единственный экземпляр, геометрия экрана. Windows-реализации переносятся как есть, для мака — заглушки. Windows-модули импортируются лениво. Windows-тесты помечаются `skipUnless(sys.platform == "win32")` | `python -c "import main"` на маке без ошибок; кроссплатформенные тесты зелёные; на Windows поведение не изменилось |
| 2 | **Локальный Whisper.** `core/stt_local.py` с интерфейсом `ElevenLabsClient.transcribe`, выбор движка по чипу, фоновая загрузка модели и прогрев, настройки `stt_engine` / `whisper_model` / язык. Для маков это значение по умолчанию. Скрипт-бенчмарк на WAV-файле | Юнит-тесты с моком движка; бенчмарк на реальном WAV (RU/UK/EN) выдаёт правильный текст; замерено время |
| 3 | **Хоткей и вставка — первый сквозной MVP без UI.** Хоткей через pynput `Key`, по умолчанию правый Option, модификатор кода. Вставка Cmd+V с сохранением и восстановлением буфера обмена. Звуки старта и стопа | Из терминала: зажал правый Option → сказал фразу → текст появился в TextEdit, Notes, браузере и мессенджере. Быстрые повторные нажатия не ломают клипы |
| 4 | **Menu bar и окна.** Спайк: pystray `run_detached` + Tk в главном потоке против **rumps** в главном потоке с окнами настроек и истории customtkinter в **отдельном процессе**. Выбрать рабочий вариант, перенести меню трея. Статус записи — в иконке | Иконка в menu bar, меню работает, настройки и история открываются и сохраняют изменения, приложение не падает при открытии и закрытии окон |
| 5 | **Mute, автозапуск, единственный экземпляр, оверлей.** Mute системного вывода через osascript (выключен по умолчанию, прежнее состояние восстанавливается даже при сбое). LaunchAgent. Lock-файл. Минимальный оверлей, если спайк этапа 4 позволяет | Запись глушит звук и возвращает его; после перезагрузки приложение стартует само; второй экземпляр не запускается |
| 6 | **Сборка `.app`.** PyInstaller `BUNDLE`, `info_plist` с `NSMicrophoneUsageDescription`, ad-hoc подпись, модель вне бандла (кэш Hugging Face или папка в `~/Library/Application Support/VoiceDrop`), конфиги и лог там же. Инструкция по разрешениям | `.app` из Finder: запрос микрофона, работа после выдачи разрешений, работа после перезапуска |
| 7 | **Качество.** Словарь терминов через `initial_prompt` Whisper (аналог `keyterms`, если API движка это поддерживает), RU/UK-автоопределение и «Переписать последнее», опциональная полировка через Claude (ключ Anthropic — по желанию) | Типичные термины пользователя распознаются; «Переписать последнее» работает на локальной модели |

**Бэклог после v1:** заглушение отдельных приложений через Core Audio taps; оверлей с живым уровнем звука; проверка «некуда вставить» через Accessibility API; подпись Developer ID и нотаризация.

## Риски

- **Главный поток на маке** (этап 4) — самый вероятный блокер: трей и Tk-окна претендуют на один поток. Поэтому сначала спайк, а окна в отдельном процессе — рабочий запасной вариант.
- **Разрешения TCC.** При пересборке `.app` macOS может заново спрашивать разрешения. Документировать для пользователя; подписывать стабильно (ad-hoc или сертификатом).
- **Первая загрузка модели** — 1.6 ГБ. Без индикации пользователь решит, что приложение зависло.
- **Intel-маки** — медленнее, и pywhispercpp придётся собирать. Если колёс нет, взять faster-whisper на CPU и модель `small` или `base`.
- **Не переносить Windows-специфичные «лечения» микрофона** (README → раздел про GRANDSTREAM, ретраи на `-9999`) без проверки: на Core Audio этих багов может не быть. Логику ретраев оставить, пороги подобрать заново.
