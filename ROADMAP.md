# VoiceDrop — Roadmap улучшений v2 (составлен 2026-06-12)

Источники: анализ боевых логов `C:\Tools\VoiceDropExe\voicedrop.log` (101 642 строки, 22.05–12.06),
полный аудит кодовой базы, исследование актуальных возможностей ElevenLabs STT (июнь 2026).

**Как пользоваться:** пункты самодостаточны — каждый можно отдать модели-исполнителю
(Opus) отдельной задачей. Приоритеты: **P0** = критично/сломается, **P1** = заметная
польза, **P2** = качество жизни, **P3** = опционально. Трудоёмкость: S (< 1 ч), M (1–4 ч), L (день+).

**Рекомендуемый порядок:** блок A целиком (особенно A1 — жёсткий дедлайн 9 июля 2026),
затем B1–B4 (бесплатные улучшения качества), затем C и D по мере желания.

### A2. Dead-letter для pending-очереди: не ретраить постоянные ошибки ✅ DONE

### A3. `commit_throttled` не должен быть фатальным ✅ DONE
**P0 · M · `core/elevenlabs_ws.py:69-82`, `main.py` (realtime-обработчик)** — выполнено (commit A2+A3, 2026-06-12).
Факт из лога: 5 случаев `commit_throttled` («only 0.00s/0.12s of uncommitted audio»).
Сейчас событие в `_FATAL_EVENTS` → весь клип падает в pending+batch. Две беды:
(а) для длинного клипа, где VAD уже всё закоммитил (0.00s uncommitted), текст ЕСТЬ,
но мы его выбрасываем и платим второй раз за батч-транскрибацию того же аудио;
(б) для совсем короткого клипа (<0.3 с) фолбэк кладёт в pending заведомо непроходной
WAV → это и есть источник «отравленных» элементов из A2.
Фикс: убрать `commit_throttled` из `_FATAL_EVENTS`; если есть закоммиченные сегменты —
вернуть собранный текст как успех; если нет и аудио < 0.3 с — отбросить клип как
too-short (бип, без pending).
Критерий: юнит-тесты на оба сценария в `tests/test_elevenlabs_ws.py`.

### A4. Микрофон `-9999 device out of range`: умный ретрай с re-resolve ✅ DONE
**P0 · M · `core/audio_recorder.py:167-217`** — выполнено (commit A4, 2026-06-12): 5 попыток, backoff 0.2/0.4/0.8/1.2с, re-resolve по имени каждую попытку, ретраим И -9999, И «не найден» (устройство переэнумерируется), overlay «Подключаю микрофон…».
Ошибка продолжается после майских фиксов: 03.06, 08.06, 10.06 (×5), 11.06 (×2), 12.06 (×4).
Паттерн сегодняшнего утра: 4 нажатия подряд за 2.5 с — все неудачны, через ~20 с само
заработало (похоже на USB-suspend FOX / переэнумерацию Windows). Текущие 2 попытки
по ~180 мс не перекрывают окно «просыпания». Фикс: при `-9999` перед каждой повторной
попыткой заново резолвить устройство ПО ИМЕНИ (индекс мог сместиться), увеличить
до 4–5 попыток с backoff 0.2/0.4/0.8/1.2 с (итого ~2.5 с — приемлемо, т.к. юзер всё
равно держит хоткей и говорит); буферить ничего не надо — главное успеть открыть стрим.
В overlay показывать «Подключаю микрофон…». НЕ возвращать sd._terminate/_initialize
(см. memory mic-saga-state — это уже проверенный тупик).
Критерий: залог в лог каждой попытки; живой тест после простоя USB.

## B. ElevenLabs API: цена/качество (главные находки исследования)

### B1. `no_verbatim` — бесплатное удаление филлеров на стороне STT
**P1 · S · `core/elevenlabs_ws.py` (query param), `core/elevenlabs_api.py` (form field)**
Scribe v2 (батч с 2026-03-09, realtime с 2026-05-04) умеет сам убирать «э-э-э», «м-м»,
фальстарты и заикания — ровно то, что сейчас делает Haiku-polish, но бесплатно и без
латентности. В логах видно, что realtime сейчас возвращает «е-е-е, дооо цього будинкууу» —
с `no_verbatim` это исчезнет до polish. Сделать настройкой `settings.stt_no_verbatim`
(default true). Polish оставить для пунктуации/структуры — но см. C2.
Критерий: живой тест — филлеры исчезают из сырого транскрипта.

### B2. `keyterms` — словарь-подсказка для распознавания
**P1 · M · `core/elevenlabs_ws.py`, `core/elevenlabs_api.py`, новый `keyterms.json`**
Scribe v2 поддерживает биасинг: батч до 1000 терминов × 50 символов, realtime до 50 × 20.
Идеально для постоянно искажаемых слов: имена, бренды, технические термины
(«VoiceDrop», «Scribe», «PyInstaller», украинские фамилии). Новый hot-reload файл
`keyterms.json` рядом с exe (по образцу `replacements.json` — content-compare, seed
defaults). ВНИМАНИЕ: батч-keyterms = +20% к цене (+$0.05/час) — сделать опцией
`settings.keyterms_enabled` (default false) и написать про наценку в README.
Критерий: термин из списка распознаётся корректно в живом тесте.

### B3. `commit_strategy=vad` на realtime WS
**P1 · M · `core/elevenlabs_ws.py:133-136`**
Сейчас WS работает в default-режиме manual commit. Серверный VAD-коммит
(`commit_strategy=vad` + `vad_silence_threshold_secs`) — рекомендованный ElevenLabs
режим для микрофонного ввода: сервер сам сегментирует, исчезает класс ошибок
`commit_throttled` (дополняет A3), потенциально быстрее финализация хвоста.
Прогнать A/B с текущей схемой на длинном клипе; параметры VAD вынести в settings
(advanced). Если ок — сделать default.
Критерий: 4-минутный клип транскрибируется полностью, без потери хвоста (регресс-тест сценария из commit 1f5696f).

### B4. Раздельный учёт стоимости batch/realtime
**P1 · S · `core/usage_tracker.py`, `main.py:998-1096`, `gui/history_window.py`**
Проверенные актуальные цены: батч **$0.22/час**, realtime **$0.39/час** (overage, все
тарифы). Текущий дефолт `stt_cost_per_hour=0.40` завышает батч почти вдвое. Фикс:
`usage_tracker.record()` принимает `mode` («batch»/«realtime»), копит минуты раздельно;
две ставки в settings (`stt_cost_batch=0.22`, `stt_cost_realtime=0.39`); tray «Расход
ElevenLabs» и футер History показывают разбивку.
Критерий: после миграции usage.json старые данные не теряются (считать их batch).

### B5. `previous_text` при реконнекте WS
**P2 · S · `core/elevenlabs_ws.py`**
Realtime API принимает `previous_text` в `input_audio_chunk` для восстановления контекста.
Если добавим авто-реконнект при обрыве WS посреди записи (сейчас — фатал + фолбэк
в батч), передавать уже закоммиченный текст для бесшовного продолжения.
Делать вместе с B3 или после него.

### B6. Язык-детект из realtime: бейдж и история
**P2 · S · `core/elevenlabs_ws.py`, `gui/recording_overlay.py`, `core/db_manager.py`**
WS умеет `include_language_detection` — сервер сообщает определённый язык сегмента.
Показывать бейдж «RU»/«UK»/«EN» в overlay при транскрибации и сохранять язык в
историю (колонка + фильтр). Полезно для контроля качества RU/UK-микса.

### B7. Fallback-провайдер для pending-очереди (Groq) — опционально
**P3 · L · новый `core/fallback_stt.py`**
Groq whisper-large-v3-turbo = $0.04/час (в 5.5 раза дешевле батча ElevenLabs), без
стриминга, но 200x realtime — для пуш-ту-толк клипов из pending-очереди скорость
неважна. Идея: при `system_busy`/5xx от ElevenLabs (5 случаев в логе) pending-ретрай
может пробовать Groq как резерв (опция, default off, нужен свой ключ). Качество RU/UK
у Whisper ниже Scribe — только как аварийный резерв, не замена.

### B8. Webhook-режим для очень длинных записей
**P3 · M · `core/elevenlabs_api.py`**
Батч поддерживает `webhook=true` (async). Для клипов > 5 минут можно не держать
HTTP-соединение 60+ секунд. Сложно без публичного endpoint — реалистичнее поднять
лимит `request_timeout_sec` пропорционально длине клипа (сейчас фикс 60 с — 10-минутный
клип может не успеть). Минимум: динамический таймаут `max(60, audio_sec * 2)`.

## C. Латентность (отпустил хоткей → текст в окне)

### C1. Адаптивный drain хвоста realtime по таймстемпам
**P1 · M · `core/elevenlabs_ws.py:53-62`**
Сейчас после каждого committed ждём `_TAIL_IDLE_SEC=2.5` с — это чистая добавка к
латентности каждого клипа (в логах: финал через ~2.5 с после последнего сегмента).
Включить `committed_transcript_with_timestamps` и завершать сессию сразу, как только
закоммиченные таймстемпы покрывают всё отправленное аудио (длительность известна).
2.5 с оставить как fallback-страховку. Ожидаемый выигрыш: −1.5…−2 с на каждый клип.
Критерий: регресс-тест многосегментного клипа (7 сегментов / 4 мин — сценарий 1f5696f) без потери текста.

### C2. Пропуск polish, когда он не нужен
**P1 · S · `main.py` (пайплайн), `core/text_polisher.py`**
Polish добавляет 1.2–3.6 с (по логам). После B1 (no_verbatim) сырой текст уже чистый
от филлеров, а пунктуацию Scribe ставит сам. Добавить: (а) пропуск polish для коротких
текстов (< N слов, настройка, default 8); (б) опцию «polish только по модификатору»
для тех, кто хочет максимум скорости. Code-режим уже пропускает polish — расширить логику.

### C3. Промпт-кэширование для polish
**P2 · S · `core/text_polisher.py:87-112`**
System-промпт polish статичен — добавить `cache_control: {type: "ephemeral"}` на

(кэш живёт 5 мин — типичный интервал между диктовками меньше).

### C4. Кэш списка PortAudio-устройств
**P2 · S · `core/audio_recorder.py:263-282`**

### C5. Единый замер латентности пайплайна
**P2 · S · `main.py`**
Сейчас тайминги размазаны («Transcribed in X», «Polished in X», realtime session stats).

Это база для оценки всех улучшений раздела C. Опционально — показывать total в History.

### C6. Тёплый WS-коннект
**P3 · M · `main.py` (нажатие хоткея), `core/elevenlabs_ws.py`**
WS-коннект занимает ~300 мс уже внутри сессии. Realtime биллится по отправленному

**P1 · L · `core/hotkey_manager.py`, `main.py`, новый full-screen Tk-попап**
Продиктовано в живом тесте сессии 1. Опциональный (НЕ замена PTT) режим:
нажал отдельную клавишу/хоткей один раз → запись идёт сама, ничего держать не
надо, можно полноценно работать за компьютером; нажал ещё раз → стоп.
Защита от случайного нажатия и слива ресурсов: каждые 3 минуты непрерывной
записи — full-screen попап «Идёт автоматическая запись разговора. Продолжаем?»;
если не подтвердили в окне — запись авто-останавливается (интервал в settings).
Заодно снимает жалобу на мышь: сейчас при зажатом PTT-хоткее (Ctrl+Shift)
не работает скролл — это `Ctrl+scroll`=zoom / `Shift+scroll`=гориз. прокрутка
на стороне Windows, НЕ баг VoiceDrop (мышь мы не перехватываем). В toggle-режиме
модификаторы не зажаты → мышь, включая колёсико, работает на 100% сама собой.
НЕ перехватывать мышь — достаточно дать toggle-режим. Детали в memory
[[toggle-recording-mode]]. Держать PTT дефолтом, toggle — opt-in.
Критерий: tap-start/tap-stop работает без зажатия; 3-мин попап появляется и
авто-стопит при отсутствии подтверждения; скролл мышью свободен в toggle-режиме.
