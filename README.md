# VoiceDrop 🎙️

Десктопное приложение для голосового ввода (диктовки) — локально-приватный конкурент WhisperFlow.
Push-to-talk: зажал клавишу — говоришь, отпустил — текст распознаётся, очищается и вставляется в активное окно.

- **Захват микрофона** по горячей клавише (push-to-talk), резолв устройства по имени.
- **Распознавание** через онлайн ElevenLabs Speech-to-Text (`scribe_v1`).
- **Постобработка текста:** LLM-полировка (Claude Haiku), словарь терминов, голосовые команды форматирования, профили Текст/Код.
- **Авто-вставка** в активное окно (буфер / в окно / в окно + Enter).
- **Глушение** других аудио-сессий на время записи (pycaw) с редактируемым белым списком.
- **История** в SQLite (поиск, экспорт, настраиваемый срок хранения), учёт расхода ElevenLabs.
- **Надёжность:** ретраи/офлайн-очередь, видимость крашей, автозапуск с Windows.
- **GUI:** системный трей (pystray) + customtkinter + оверлей записи.

**Стек:** Python 3.13 · httpx · sounddevice/soundfile · pynput · pyperclip · pystray/Pillow · customtkinter · apscheduler · pywin32 · pycaw · psutil · python-dotenv.
Платформа: **Windows 10/11** (хоткеи, вставка, глушение, автозапуск — Windows-специфичны).

## Быстрый старт

1. Рядом с exe в `.env`: `ELEVENLABS_API_KEY=...` (обязательно) и, для LLM-полировки, `ANTHROPIC_API_KEY=...` (опционально).
2. Запусти `VoiceDrop.exe` — иконка появится в системном трее.
3. **Зажми хоткей** (по умолчанию — **правый Ctrl**), говори, **отпусти** — текст вставится.
4. ПКМ по иконке в трее — всё меню (см. ниже).

### Горячие клавиши
- **Правый Ctrl** (по умолчанию) — обычная диктовка. Хранится **VK-кодами** в `settings.json` → не зависит от раскладки/языка системы.
- **Правый Ctrl + правый Shift** — эта диктовка идёт в **код-режиме** (verbatim, без полировки), без переключения в трее. Модификатор настраивается (`code_modifier`, по умолчанию 161).
- Левый Ctrl и его шорткаты (Ctrl+C/V) запись **не** запускают — правые модификаторы матчатся точно.
- Сменить хоткей: Настройки или `settings.json` (`hotkey.keys`).

## Постобработка текста (качество)

Пайплайн: распознал → **полировка** → **словарь** → **голосовые команды** → **код-стиль** → вставка.

- **LLM-полировка** (трей → «Полировка текста») — Claude Haiku убирает «э/ну/вот/как бы/типа», правит пунктуацию и регистр, сохраняет смысл и язык. Требует `ANTHROPIC_API_KEY`. Best-effort: при сбое возвращается исходный текст. Только в режиме «Текст».
- **Словарь терминов** — `replacements.json` (горячий): «произнёс → канон», напр. «элевен лабс → ElevenLabs», с учётом падежей. Добавляй свои термины.
- **Голосовые команды** — `commands.json` (горячий): «новая строка», «новый абзац», «код блок», «новый пункт», «табуляция» → реальные символы. Пунктуацию не делаем (scribe её ставит сам).
- **Аудио-теги** ElevenLabs («(смеётся)», «(тишина)») отключены (`tag_audio_events=false`) и подчищаются.

### Режим Текст / Код (трей → «Режим»)
- **Авто** — определяется по активному окну (список «код-приложений» в `profiles.json`, по умолчанию пуст → везде Текст).
- **Текст** — полировка + полная пунктуация. **Код** — verbatim, без полировки, без финальной точки, латинская команда со строчной («Git status.» → «git status»). Словарь и команды работают в обоих.

### Язык (трей → «Язык»)
- **Авто / Русский / Українська / English** — применяется к следующей записи. Для смешанной RU/UK держи Авто.
- **«Переписать последнее» → RU/UK/EN** — если язык «поплыл», та же запись пере-распознаётся принудительно (результат в буфер + История).

## Рабочий процесс

- **Режимы вставки** (трей → «Вставка»): в окно / только в буфер / **в окно + Enter** (авто-отправка в чатах).
- **Скопировать последнее** / **Переписать последнее** — быстрые действия в трее.
- **Автозапуск с Windows** (трей) — старт при входе в систему (ключ `HKCU\…\Run`).
- **Расход ElevenLabs** (трей) — запросы и минуты аудио за сегодня/всего + оценка стоимости (`stt_cost_per_hour`).

## Надёжность

- **Микрофон по имени** при каждом открытии потока (индексы на Windows плавают: один микрофон виден под MME/DirectSound/WASAPI/WDM-KS). Приоритет: MME → WASAPI → DirectSound → WDM-KS. Не найден — ошибка + уведомление, **без** тихого отката на дефолт.
- **Без гонки mute:** захват стартует первым; глушение — в фоне с grace-периодом и защитой порядка (поздний mute сам откатывается). Нет «застрявшего mute» и потери начала фразы.
- **Сеть:** ретраи с бэкоффом на 429/5xx и сетевых сбоях, учёт `Retry-After`, раздельные таймауты, детект офлайна. Параметры — в Настройках (таймаут/ретраи).
- **Очередь неотправленных:** при сетевом сбое аудио → `pending/`, авто-дослыается воркером (45 с); индикатор «Очередь: N» в трее (клик — дослать сейчас).
- **Видимость крашей:** `sys.excepthook` + `threading.excepthook` → `voicedrop_crash.log`.

## Если запись пустая («Recording too short»)

Симптом: хоткей сработал, beep слышно, но в `voicedrop.log` нет строки `Audio: wall ... / captured ...`, только `Recording too short, ignoring`. Иногда после этого `stop_recording()` блокирует поток на 10–20 с.

Это значит, что Windows MME «открыл» поток, но callback не получает ни одного буфера. Чаще всего причина — **другой USB-микрофон, который засоряет MME-перечисление**. Конкретно у нас засветилась USB-камера **GRANDSTREAM GUV3100**: её встроенный микрофон периодически вешает аудио-стек для FOX, хотя сам в VoiceDrop не используется.

Решение — отключить **только аудио-интерфейс камеры** (MI_02), оставив видео-интерфейс (MI_00). PowerShell от админа:

```powershell
# Найти ID аудио-интерфейса (MEDIA, не Camera!)
$id = (Get-PnpDevice | Where-Object {
    $_.FriendlyName -eq 'GRANDSTREAM GUV3100' -and $_.Class -eq 'MEDIA' -and $_.Status -eq 'OK'
}).InstanceId

# Отключить (сохраняется между перезагрузками)
Disable-PnpDevice -InstanceId $id -Confirm:$false

# Если когда-нибудь захочется вернуть:
# Enable-PnpDevice -InstanceId $id -Confirm:$false
```

После этого `Microphone (GRANDSTREAM GUV3100)` уходит из `sounddevice.query_devices()`, FOX занимает свой нормальный индекс под MME, callback оживает. **Камера для звонков продолжает работать** — мы трогаем только MI_02. VoiceDrop резолвит микрофон по имени, переконфигурации не требуется.

Если GRANDSTREAM не при чём — кратковременно помогает **физически переподключить FOX в USB** (Windows пере-перечисляет устройство). Если симптом возвращается без подключённого «лишнего» USB-микрофона, открывай заново историю mic-саги.

## История и приватность

- **Окно истории** (трей → «Открыть историю»): поиск по тексту, **экспорт** в `.md`/`.txt`, кнопка **«Очистить»**.
- **Срок хранения** (Настройки): 24 ч / 7 дней / 30 дней / Бессрочно.
- **«Сохранять историю»** (трей) — выключи, чтобы тексты не писались в БД.

## Структура

```
core/
  audio_recorder.py   # запись + резолв микрофона по имени
  audio_muter.py      # глушение аудио-сессий (pycaw), белый список из mute_whitelist.json
  elevenlabs_api.py   # STT-клиент: ретраи/бэкофф/таймауты/офлайн, срез аудио-тегов
  pending_queue.py    # очередь неотправленных (offline)
  hotkey_manager.py   # глобальный хоткей (VK, точный матчинг правых модификаторов + код-модификатор)
  text_inserter.py    # вставка (Win32 Ctrl+V, опц. Enter)
  text_replacer.py    # словарь терминов (replacements.json)
  text_polisher.py    # LLM-полировка (Claude Haiku)
  voice_commands.py   # голосовые команды форматирования (commands.json)
  profiles.py         # режим Текст/Код (profiles.json, авто по окну)
  usage_tracker.py    # учёт расхода (usage.json)
  autostart.py        # автозапуск (HKCU Run)
  db_manager.py       # SQLite-история (поиск/экспорт/срок/очистка)
gui/
  tray_icon.py        # трей + всё меню
  settings_window.py  # настройки (микрофон, язык, хоткей, срок хранения, доп.)
  recording_overlay.py# оверлей записи/обработки/ошибки
  history_window.py   # окно истории (поиск/экспорт/очистка)
main.py · config.py · VoiceDrop.spec
```

### Файлы рядом с exe (все, кроме .env, создаются автоматически)
`.env` (ключи API) · `settings.json` · `replacements.json` · `commands.json` · `profiles.json` · `mute_whitelist.json` · `usage.json` · `voicedrop.db` · `voicedrop.log` · `voicedrop_crash.log` (при крашах) · `pending/`.
Все конфиг-JSON редактируются «на лету» (горячая перезагрузка) и сидируются дефолтами при первом запуске.

## Сборка и запуск (разработка)

Окружение — venv в `.venv` (Python 3.13):

```powershell
# Запуск из исходников
.\.venv\Scripts\python.exe main.py

# Сборка exe (в dist\, не трогает работающий exe)
.\.venv\Scripts\python.exe -m PyInstaller VoiceDrop.spec --noconfirm `
  --distpath .\dist --workpath .\build
```

Деплой: остановить `VoiceDrop.exe`, скопировать `dist\VoiceDrop.exe` на место, запустить.
Настройки/база/.env рядом с exe сохраняются — меняется только бинарник.

> ⚠️ Не запускай dev-версию одновременно с рабочим exe — оба перехватят один глобальный хоткей.
