# VoiceDrop 🎙️

Десктопное приложение для голосового ввода (диктовки) — локально-приватный конкурент WhisperFlow.
Push-to-talk: зажал клавишу — говоришь, отпустил — текст распознаётся и вставляется в активное окно.

- **Захват микрофона** по горячей клавише (push-to-talk).
- **Распознавание** через онлайн ElevenLabs Speech-to-Text (`scribe_v1`).
- **Авто-вставка** текста в активное окно (через буфер обмена).
- **Глушение** других аудио-сессий на время записи (pycaw), с белым списком (браузеры, мессенджеры не глушатся).
- **История** записей в SQLite (хранение 24 ч), окно истории с копированием.
- **GUI:** системный трей (pystray) + customtkinter + оверлей записи с визуализацией уровня.

**Стек:** Python · httpx · sounddevice/soundfile · pynput · pyperclip · pystray/Pillow · customtkinter · apscheduler · pywin32 · pycaw · python-dotenv.
Платформа: **Windows 10/11** (часть функций — хоткеи, вставка, глушение — Windows-специфичны).

## Использование

1. В `.env` рядом с exe должен быть ключ: `ELEVENLABS_API_KEY=...`
2. Запусти `VoiceDrop.exe` — иконка появится в системном трее.
3. **Зажми хоткей** (по умолчанию — **правый Ctrl**), говори, **отпусти** — текст вставится в активное окно.
4. ПКМ по иконке в трее: **История**, **Язык**, **Настройки**, **Выход**.

### Горячая клавиша
- Хранится **VK-кодами** в `settings.json` → работает **независимо от раскладки/языка системы**.
- По умолчанию — одиночный **правый Ctrl** (VK 163). Левый Ctrl и его шорткаты (Ctrl+C/V и т.д.) запись **не** запускают.
- Правые модификаторы (правый Ctrl/Shift/Alt/Win) сопоставляются **точно** (без слияния лево/право), поэтому их можно использовать как выделенную PTT-клавишу.
- Сменить можно в Настройках или прямо в `settings.json` (поле `hotkey.keys`).

### Язык распознавания
- Быстрый переключатель в трее: **Язык → Авто / Русский / Українська / English**. Применяется к следующей же записи.
- Для смешанной RU/UK речи держи **Авто**; на блок одноязычной диктовки можно зафиксировать конкретный язык, чтобы исключить «перетекание».

## Надёжность (что отличает от прототипа)

- **Микрофон резолвится ПО ИМЕНИ** при каждом открытии потока, а не по индексу. На Windows один физический микрофон виден под несколькими host API (MME/DirectSound/WASAPI/WDM-KS) и индексы плавают — поэтому выбор по индексу приводил к «сбросу» на чужой микрофон. Приоритет host API: MME → WASAPI → DirectSound → WDM-KS. Если сохранённый микрофон не найден — **явная ошибка + уведомление**, без тихого отката на системный по умолчанию.
- **Запись не теряется на быстрых/случайных нажатиях:** захват стартует первым, глушение уходит в фоновый поток с grace-периодом и защитой порядка (поздний mute сам себя откатывает) — нет «застрявшего mute» и потери начала фразы.
- **Сеть устойчива:** ретраи с экспоненциальным бэкоффом (0.8/1.6/3.2 с) на 429/5xx и транзиентных сетевых ошибках, учёт `Retry-After`, раздельные таймауты (connect 10 с / read 60 с), детект офлайна.
- **Очередь неотправленных:** если транскрибация не удалась из-за сети — аудио сохраняется в `pending/` и **авто-дослыается** фоновым воркером (каждые 45 с); восстановленный текст попадает **в Историю** (не вставляется в активное окно) + уведомление.
- **Видимость крашей:** глобальные `sys.excepthook` + `threading.excepthook` пишут любые необработанные исключения в `voicedrop_crash.log`.

## Структура

```
core/
  audio_recorder.py   # запись + резолв микрофона по имени
  audio_muter.py      # глушение аудио-сессий (pycaw) с белым списком
  elevenlabs_api.py   # клиент STT: ретраи/бэкофф/таймауты/офлайн
  pending_queue.py    # очередь неотправленных записей
  hotkey_manager.py   # глобальный хоткей (VK-коды, точный матчинг правых модификаторов)
  text_inserter.py    # вставка текста (Win32 Ctrl+V)
  db_manager.py       # SQLite-история
gui/
  tray_icon.py        # трей + меню (язык, история, настройки)
  settings_window.py  # настройки (микрофон, язык, хоткей) + load/save_settings
  recording_overlay.py# оверлей записи/обработки/ошибки
  history_window.py   # окно истории
main.py               # точка входа, оркестрация
config.py             # пути (dev/PyInstaller), константы
VoiceDrop.spec        # сборка PyInstaller
```

### Файлы рядом с exe
`.env` (ключ API) · `settings.json` (микрофон/язык/хоткей) · `voicedrop.db` (история) · `voicedrop.log` · `voicedrop_crash.log` (при крашах) · `pending/` (неотправленные записи).

## Сборка и запуск (разработка)

Окружение — venv в `.venv` (Python 3.13):

```powershell
# Запуск из исходников
.\.venv\Scripts\python.exe main.py

# Сборка exe (в dist\, не трогает уже работающий exe)
.\.venv\Scripts\python.exe -m PyInstaller VoiceDrop.spec --noconfirm `
  --distpath .\dist --workpath .\build
```

Деплой собранного exe в рабочую папку: остановить запущенный `VoiceDrop.exe`, скопировать
`dist\VoiceDrop.exe` на место, запустить. Настройки/база/.env рядом с exe сохраняются —
меняется только бинарник.

> ⚠️ Не запускай dev-версию из исходников одновременно с рабочим exe — оба перехватят
> один и тот же глобальный хоткей.
