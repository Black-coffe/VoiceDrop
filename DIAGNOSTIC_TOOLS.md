# Диагностические инструменты VoiceDrop

## Проблема

Если ваше приложение VoiceDrop автоматически закрывается при запуске других Python проектов (PyCharm, VS Code и т.д.), это может быть связано с:

1. Скриптами, убивающими Python процессы
2. Настройками IDE, управляющими процессами
3. Антивирусом или защитным ПО
4. Конфликтами между процессами

## Улучшения в коде

### 1. Защищенный Mutex
- Mutex теперь хранится как глобальная переменная `_APP_MUTEX`
- Уникальное имя на основе пути: `Global\VoiceDrop_C_Tools_VoiceDrop_main.py`
- Автоматическое освобождение при выходе
- Защита от сборщика мусора

### 2. Расширенное логирование
- Все события записываются в `voicedrop.log`
- Логи помогут понять, почему приложение закрылось
- Информация о сигналах SIGTERM/SIGINT
- Подробности об ошибках с stack trace

### 3. Обработка сигналов завершения
- Graceful shutdown при получении SIGTERM или SIGINT
- Гарантированное размьютирование аудио перед выходом
- Защита от повторного вызова shutdown

## Диагностические инструменты

### diagnose.bat - Мониторинг процессов

**Что делает:**
- Показывает все Python процессы в системе
- Обнаруживает VoiceDrop среди них
- Следит за завершением процессов в реальном времени
- Предупреждает, если VoiceDrop закрывается

**Как использовать:**
```bash
# 1. Запустите VoiceDrop
run.bat

# 2. В новом окне запустите диагностику
diagnose.bat

# 3. Работайте как обычно (запускайте PyCharm, другие проекты)
# 4. Смотрите, что происходит с процессами
```

**Что вы увидите:**
- Список всех Python процессов с PID и командной строкой
- Уведомление, когда VoiceDrop обнаружен
- **ALERT**, если какой-то Python процесс завершается
- Указание, если это был VoiceDrop
- Возможные причины проблемы

### run_with_watchdog.bat - Автоматический перезапуск

**Что делает:**
- Запускает VoiceDrop
- Постоянно следит за ним
- Автоматически перезапускает при сбое
- Логирует все перезапуски

**Как использовать:**
```bash
# Запустите VoiceDrop с защитой
run_with_watchdog.bat
```

**Особенности:**
- Автоматический перезапуск при неожиданном закрытии
- Лог в файле `watchdog.log`
- Защита от бесконечных перезапусков (если сбой < 10 сек, останавливается)
- Счетчик перезапусков

**Когда использовать:**
- Если вы знаете, что что-то убивает процесс, но хотите продолжать работу
- Для временного решения проблемы
- Чтобы собрать статистику о частоте сбоев

## Пошаговая диагностика

### Шаг 1: Проверьте логи

```bash
# Откройте лог-файл приложения
notepad voicedrop.log
```

Ищите:
- `Received signal` - указывает на принудительное завершение
- `Shutting down...` - нормальный выход
- Ошибки и исключения

### Шаг 2: Запустите мониторинг

```bash
# Терминал 1: VoiceDrop
run.bat

# Терминал 2: Мониторинг
diagnose.bat
```

Теперь запустите то, что обычно "убивает" VoiceDrop (PyCharm, другой проект).

### Шаг 3: Анализ результатов

**Если diagnose.bat показывает, что VoiceDrop завершается:**

1. **Смотрите время** - если это происходит сразу после запуска другого проекта, проблема в конфликте
2. **Проверьте Task Scheduler** - возможно есть задача, убивающая процессы
3. **Проверьте IDE** - возможно PyCharm управляет Python процессами

**Если в voicedrop.log есть "Received signal":**
- Что-то извне послало сигнал завершения
- Проверьте антивирус, скрипты автоматизации

**Если логи пустые или обрываются:**
- Процесс был убит насильно (kill -9 / taskkill /F)
- Проверьте системные логи Windows

### Шаг 4: Временное решение

Пока вы ищете причину, используйте watchdog:

```bash
run_with_watchdog.bat
```

## Поиск виновника

### 1. Task Scheduler

```powershell
# Открыть Task Scheduler
taskschd.msc
```

Ищите задачи с:
- `python` в имени или команде
- `taskkill` в действиях
- Триггерами на запуск приложений

### 2. Автозапуск скрипты

Проверьте папки:
- `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup`
- `C:\ProgramData\Microsoft\Windows\Start Menu\Programs\Startup`

### 3. PowerShell профили

```powershell
# Проверить профили PowerShell
notepad $PROFILE
notepad $PROFILE.AllUsersAllHosts
```

### 4. IDE настройки

**PyCharm:**
- Settings → Tools → Python Integrated Tools
- Settings → Build, Execution, Deployment → Python Debugger

**VS Code:**
- Проверьте расширения Python
- Настройки управления процессами

### 5. Антивирус

Добавьте в исключения:
- Папку: `C:\Tools\VoiceDrop`
- Процесс: `pythonw.exe` из `.venv\Scripts\`

## Полезные команды

### Показать все Python процессы
```powershell
Get-Process | Where-Object {$_.ProcessName -like "*python*"} | Format-Table Id, ProcessName, Path
```

### Найти, кто запустил процесс
```powershell
wmic process where "name='python.exe'" get ProcessId,ParentProcessId,CommandLine
```

### Проверить сетевые соединения Python
```powershell
netstat -ano | findstr "python"
```
